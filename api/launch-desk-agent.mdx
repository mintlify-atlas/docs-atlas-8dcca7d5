The Launch Desk agent is the AI brain behind AI Surfer's release planning workflow. It is instantiated as an `Agent` from the `@openai/agents` SDK and registered with four deterministic planning tools that score readiness, extract tasks, build owner checklists, and draft channel copy — all grounded strictly in what the submitted brief actually contains.

## Agent Identity

The `launchDeskAgent` is constructed once at module load time and reused across requests. It carries a fixed name, a configurable model, a detailed system prompt, and four tool registrations.

```typescript server/agent/launchDeskAgent.ts
import { Agent } from "@openai/agents";
import {
  draftChannelCopyTool,
  extractLaunchTasksTool,
  checkLaunchReadinessTool,
  generateOwnerChecklistTool,
} from "../tools/launchTools";

export const launchDeskAgent = new Agent({
  name: "Launch Desk",
  model: process.env.OPENAI_MODEL || "gpt-5.6-terra",
  instructions: `You are Launch Desk, a pragmatic engineering launch planner...`,
  tools: [
    extractLaunchTasksTool,
    checkLaunchReadinessTool,
    generateOwnerChecklistTool,
    draftChannelCopyTool,
  ],
});
```

## System Instructions

The agent's instructions encode a strict behavioral contract. The most important rules are:

- **Ground every recommendation in the supplied brief.** Do not invent product capabilities, dates, approvals, metrics, or assets.
- **State assumptions explicitly** when the brief is ambiguous.
- **Prioritize by** launch impact, dependencies, urgency, and reversibility.
- **Use tools proactively:** call `extract_launch_tasks` and `check_launch_readiness` whenever their inputs are available; call `generate_owner_checklist` and `draft_channel_copy` when the request includes enough context.
- **Never expose** internal tool schemas or API keys in any response.

## Required Output Sections

Every agent run produces a markdown response containing exactly these six headings, in order:

<Steps>
  <Step title="Launch Snapshot">
    A concise overview of the launch: what is shipping, to whom, and by when — drawn only from the brief.
  </Step>
  <Step title="Priority Plan">
    Concrete actions with owners, timing, dependencies, and explicit **P0 / P1 / P2** priority labels. No action may appear without an owner role and at least an approximate timing.
  </Step>
  <Step title="Risk Register">
    Each risk includes **likelihood**, **impact**, **mitigation**, and **owner role** where inferable from the brief.
  </Step>
  <Step title="Owner Checklist">
    Tasks grouped by owner role, generated by the `generate_owner_checklist` tool, with P0 items flagged as pre-go/no-go gates.
  </Step>
  <Step title="Launch Copy">
    Channel-specific draft copy produced by `draft_channel_copy`, one entry per requested channel.
  </Step>
  <Step title="Follow-up Questions">
    Only questions about missing details that materially affect readiness. If nothing material is missing, the agent states that explicitly.
  </Step>
</Steps>

## Input Schema — LaunchBrief

The `LaunchBriefSchema` is defined with Zod and validated by the HTTP handler before the agent is invoked. Invalid briefs are rejected with a `400`-equivalent SSE error event before the agent is ever called.

```typescript server/agent/types.ts
import { z } from "zod";

export const LaunchBriefSchema = z.object({
  productBrief:  z.string().min(20),
  audience:      z.string().min(3),
  launchDate:    z.string().min(4),
  constraints:   z.string().default("None specified"),
  assets:        z.string().default("None specified"),
  channels:      z.array(z.string()).min(1),
});

export type LaunchBrief = z.infer<typeof LaunchBriefSchema>;
```

<ParamField body="productBrief" type="string" required>
  A description of what is being launched. Must be at least 20 characters. Longer, more detailed briefs (>120 chars) unlock higher Product and Measurement readiness scores.
</ParamField>

<ParamField body="audience" type="string" required>
  The intended audience for the launch. Minimum 3 characters. Used in channel copy generation as the addressee.
</ParamField>

<ParamField body="launchDate" type="string" required>
  The target launch date. Minimum 4 characters — accepts any human-readable date format (e.g. `"2025-09-01"`, `"Q3 2025"`).
</ParamField>

<ParamField body="constraints" type="string">
  Known constraints, blockers, or budget limits. Defaults to `"None specified"` if omitted. Including the word `"approval"` raises the Stakeholders readiness score.
</ParamField>

<ParamField body="assets" type="string">
  Available launch assets such as copy, email templates, or design files. Defaults to `"None specified"`. Including `"copy"` or `"email"` raises the Communications readiness score.
</ParamField>

<ParamField body="channels" type="string[]" required>
  One or more distribution channels for which copy should be drafted (e.g. `["email", "social", "blog"]`). Must contain at least one entry.
</ParamField>

## Supporting Types

### LaunchTask

Tasks produced by `extract_launch_tasks` and consumed by both `generate_owner_checklist` and `check_launch_readiness`.

```typescript server/agent/types.ts
export const LaunchTaskSchema = z.object({
  title:      z.string(),
  priority:   z.enum(["P0", "P1", "P2"]),
  dependency: z.string(),
  ownerRole:  z.string(),
  rationale:  z.string(),
});

export type LaunchTask = z.infer<typeof LaunchTaskSchema>;
```

### Readiness

The structured readiness report returned by `check_launch_readiness`.

```typescript server/agent/types.ts
export const ReadinessSchema = z.object({
  score:      z.number().min(0).max(100),
  status:     z.enum(["ready", "at-risk", "blocked"]),
  categories: z.array(z.object({
    category: z.string(),
    score:    z.number(),
    gap:      z.string(),
  })),
  blockers:   z.array(z.string()),
});

export type Readiness = z.infer<typeof ReadinessSchema>;
```

<ResponseField name="score" type="number">
  Aggregate readiness score from 0–100, computed as the mean of the six category scores.
</ResponseField>

<ResponseField name="status" type="string">
  One of `"ready"` (score ≥ 80), `"at-risk"` (score ≥ 65), or `"blocked"` (score < 65).
</ResponseField>

<ResponseField name="categories" type="object[]">
  One entry per scored dimension — see [Launch Tools](/api/launch-tools) for scoring logic per category.
</ResponseField>

<ResponseField name="blockers" type="string[]">
  Human-readable descriptions of every category scoring below 60, surfaced to the agent for risk register generation.
</ResponseField>

## Streaming Architecture

The HTTP handler pre-runs two tools synchronously before invoking the agent, then streams agent output as Server-Sent Events. Consumers receive a sequence of typed events.

```typescript server/api/launch.ts
import { run } from "@openai/agents";
import { launchDeskAgent } from "../agent/launchDeskAgent";

// Pre-flight: run tools synchronously and inject results into the prompt
const tasks     = extractLaunchTasks({ productBrief: brief.productBrief, constraints: brief.constraints });
const readiness = checkLaunchReadiness({ ...brief, tasks });

const prompt = `Launch context:\n${JSON.stringify(
  { ...brief, extractedTasks: tasks, readiness },
  null,
  2,
)}\n\nCreate the release plan now.`;

// Stream the agent
const stream = await run(launchDeskAgent, prompt, { stream: true });

for await (const event of stream) {
  if (event.type === "raw_model_stream_event") {
    const data = event.data as { type?: string; delta?: string };
    if (data.type === "output_text_delta" && data.delta) {
      send(res, { type: "text_delta", delta: data.delta });
    }
  }
}

await stream.completed;
send(res, { type: "final", output: stream.finalOutput });
```

### SSE Event Types

<Accordion title="tool_progress">
  Emitted before and after each tool call, both for the pre-flight synchronous calls and for any tool the agent triggers during its own reasoning.

  ```json
  { "type": "tool_progress", "tool": "extract_launch_tasks", "status": "started",   "message": "Extracting the launch critical path…" }
  { "type": "tool_progress", "tool": "extract_launch_tasks", "status": "completed",  "message": "5 launch tasks identified." }
  ```
</Accordion>

<Accordion title="text_delta">
  Incremental markdown text chunks streamed as the agent writes its response. Concatenate `delta` values in order to reconstruct the full plan.

  ```json
  { "type": "text_delta", "delta": "## Launch Snapshot\n" }
  ```
</Accordion>

<Accordion title="final">
  Sent once after `stream.completed` resolves. Contains the complete plan text.

  ```json
  { "type": "final", "output": "## Launch Snapshot\n..." }
  ```
</Accordion>

<Accordion title="error">
  Sent if the brief fails Zod validation or if the agent throws. The connection is closed immediately after.

  ```json
  { "type": "error", "message": "String must contain at least 20 character(s)" }
  ```
</Accordion>

## Environment Variables

<Note>
  Two environment variables must be set for the agent to function in any environment:

  - **`OPENAI_API_KEY`** — required for all `@openai/agents` SDK calls. Without it, every `run()` call will throw an authentication error.
  - **`OPENAI_AGENTS_DISABLE_TRACING`** — set to `"1"` to suppress OpenAI tracing if your deployment has no tracing backend configured. Omitting this in environments without tracing can produce noisy console errors.
  - **`OPENAI_MODEL`** — optional. Overrides the default model `gpt-5.6-terra` for all Launch Desk runs.
</Note>
